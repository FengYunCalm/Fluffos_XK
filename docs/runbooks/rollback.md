# 回滚运行手册（T18）

> 适用：release 失败、运行时崩溃、安全事件需要回退 driver 版本时。
> 原则：不删除历史 tag、不强推、不做未授权操作。

## 1. 判断是否需要回滚

| 症状 | 处置 |
| --- | --- |
| 新版本启动即崩溃/段错误 | 立即回滚到上一已验证版本 |
| 新版本 CPU/内存异常增长 | 保留现场（日志/核心转储）后回滚 |
| gateway 错误、queue reject、timeout 超阈值 | 停止压力，保留现场，回滚 |
| owner claim/future/object ref 持续增长 | 停止长时运行，保留现场，回滚 |
| 安全事件（漏洞利用/泄露） | 按 `gateway-security.md` 处理，必要时离线 |

## 2. 回滚步骤

1. **保留现场**：复制 `debug.log`、core dump、`build/reports/`、进程 `ps` 快照
   到安全目录，注明 commit 与运行配置；不删除日志。
2. **切换二进制**：
   - 二进制部署：换回上一版 tag 对应的资产（`git tag` 列出历史版本）。
   - Docker：`docker pull ghcr.io/<repo>:<上一版本>` 并重启服务。
3. **验证回退**：确认服务健康检查通过、无新错误增量、版本号正确。
4. **记录**：在 runbook/事故记录中写时间、触发 commit、回退目标、恢复时长、
   残留 tag/release 与客户端兼容影响。

## 3. 不回滚的情况

- 文档/证据漂移：不触发二进制回滚，走文档修正 PR。
- 新候选版本失败但未发布：无需回滚，直接修复重跑 workflow。
- 旧 tag 上发现缺陷：不回退历史 tag，在新候选版本修复并发布。

## 4. 发布流水线残留

- tag 已创建但 draft 失败：不移动或覆盖 tag，登记残留，使用新版本重新发布。
- draft 仅含部分资产：保持 draft、禁止发布，不把另一轮构建的资产补进同一版本；新版本
  重新走完整门禁。
- 不可变镜像版本已推广但 digest 复核失败：禁止更新 `latest`，保留预期值与远端值，使用
  新版本恢复。历史不可变版本引用不覆盖。
- `latest` 异常：在确认上一稳定 digest 后另行审批恢复；不得改变历史版本 tag。
- 删除残留 tag、draft 或容器引用属于单独的破坏性操作，必须明确授权并保留审计记录。

## 5. 客户端兼容

- 若协议或配置字段有破坏性变更，回滚时同时回退客户端配置；发布前必须在
  `RELEASE.md` 记录兼容性影响面。
- 镜像撤回：按容器仓库策略删除错误 tag；已拉取方通过公告引导升级/回退。
